We removed our message queue and nothing exploded

A long story about read-your-writes consistency, a 600-line consumer that became 12, and the unglamorous engineering of "obvious in retrospect."

Last quarter we removed the message queue from our checkout service. We replaced about six hundred lines of consumer plumbing with a twelve-line function. Nothing exploded. This is the longer version of what we found.

The history is mundane. Three years ago, when the team was four engineers, we punted on a tricky synchronous call by sticking a queue between two services. It worked. It was also the start of a long story about read-your-writes consistency that ended up costing us more than the original synchronous call would have.

None of this is an indictment of message queues. It is an indictment of our use of a message queue for a workload it was never the right tool for. The shape of the workload mattered more than the shape of the tool.

The original architecture

Order writes went to the primary database, then a change-data-capture stream fanned them out to a queue, and a consumer materialized them into a read model. The read model was the thing the checkout UI actually read from.

// the original consumer, roughly
async function onOrderCreated(evt) {
  const order = await db.orders.get(evt.id);
  const lines = await db.lines.where({ orderId: evt.id }).all();
  const totals = await pricing.totals(order, lines);
  await readModel.upsert(toReadRow(order, lines, totals));
}

On a quiet day, end-to-end latency was around forty milliseconds. On a less quiet day — a deploy, a slow consumer, a backed-up partition — it was whatever the consumer's lag happened to be. The UI did not know which day it was.

We tried the usual things. Read-after-write polling. A short cache. A "did you mean to refresh?" toast which I am still embarrassed about. Each one papered over the same shape of bug and left a different one behind.

What we actually wanted

What we actually wanted was a strongly-consistent read of a small, bounded view of the data, on the request path, on the same database. We were using a queue because someone had once said the word "decoupling" out loud and nobody had revisited it.
